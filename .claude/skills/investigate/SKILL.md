# 実行プロセス

1. **調査と分析**:
   - 引数 `$ARGUMENTS` で指定されたコード領域を `grep` や `read_file` を駆使して深く分析してください。
   - 関連する依存関係や、潜在的なエッジケースも特定してください。

2. **保存先の準備 (Robust Check)**:
   - 保存先ディレクトリ `./investigations/` の状態を確認してください。
   - ディレクトリが存在しない場合は作成（`mkdir -p`）してください。
   - **権限エラーが発生した場合**: カレントディレクトリ直下、またはシステムが許可する一時ディレクトリへの保存を試み、その旨をユーザーに報告してください。

3. **ユニークなファイル名の生成**:
   - 基本名: `YYYYMMDD_$1.md`（スペースはアンダースコアに置換）
   - **重複チェック**: すでに同名のファイルが存在する場合、`_v2`, `_v3` といったサフィックスを自動で付与し、既存のデータを上書きしないようにしてください。

4. **ドキュメントの作成と書き込み**:
   - 以下の構成で Markdown を記述してください：
     - # 調査報告: $1
     - ## 概要 / 実行日時
     - ## 調査対象ファイル一覧
     - ## 詳細分析
     - ## 推奨される修正案・ネクストステップ
   - `write_file` ツールを使用して、特定したユニークなパスに保存してください。

5. **完了報告**:
   - 保存したフルパスを明示し、調査の要約を1行で述べて終了してください。
