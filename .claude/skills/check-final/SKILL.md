# @final 違反チェッカー

JSDocで `@final` タグが付与されたメソッドを検出し、そのメソッドをサブクラスが不正にオーバーライドしていないかを検査する。

## 引数

- `$ARGUMENTS` — 省略可。特定のクラス名やファイルパスを指定すると、そのスコープに絞って検査する。省略した場合は Sources/ 配下の全 `.js` ファイルを対象とする。

## 実行手順

### Step 1: @final メソッドの検出

Sources/ 配下の全 `.js` ファイル（引数でスコープ指定がある場合はそのスコープ）から、JSDoc コメントに `@final` タグを含むメソッドを**すべて**検出する。

検出パターン:
- `/** ... @final ... */` の直後に定義されているメソッド名を取得
- そのメソッドが属するクラス名も特定する

各 `@final` メソッドについて、以下の情報を記録する:
- ファイルパス
- 行番号
- クラス名
- メソッド名

### Step 2: サブクラスの列挙

Step 1 で見つかった各 `@final` メソッドの宣言クラスについて:

1. そのクラスを `extends` しているクラスを Sources/ 配下から検索する
2. 見つかったサブクラスをさらに `extends` しているクラスも再帰的に検索する（間接的なサブクラスも対象）
3. すべての直接・間接サブクラスの一覧を作成する

検索パターン例: `class XxxNode extends EffectNode` や `class YyyNode extends XxxNode` など

### Step 3: 違反の検出

Step 2 で見つかった各サブクラスについて:

1. そのクラス定義の中に `@final` メソッドと同名のメソッド定義が存在するかチェックする
2. メソッド定義のパターン: クラスのボディ内に `メソッド名(` がインデントされて出現する箇所
3. JSDoc の `@override` タグの有無も確認する（ある場合は意図的なオーバーライドだが、@final 違反であることに変わりない）

**重要**: 以下は違反としてカウントしない:
- `@final` を宣言しているクラス自身のメソッド定義
- `onEvaluate` のような代替メソッド（@final の趣旨に沿った正しい実装）

### Step 4: 結果の出力

以下の形式で結果を報告する:

```
## @final 違反チェック結果

### 検出された @final メソッド
| クラス | メソッド | ファイル | 行 |
|--------|---------|---------|-----|
| ... | ... | ... | ... |

### 違反一覧
| # | 違反クラス | オーバーライドしたメソッド | 宣言元クラス | ファイル | 行 |
|---|-----------|----------------------|------------|---------|-----|
| 1 | ... | ... | ... | ... | ... |

### サマリー
- 検査対象サブクラス数: N
- 違反数: N
- 違反率: N%
```

違反が0件の場合は「違反は検出されませんでした」と報告する。

## 注意事項

- JavaScript のクラス構文（`class ... extends ...`）のみを対象とする
- プロトタイプベースの継承は対象外
- `Sources/` ディレクトリのみを検索対象とする（`Tests/`, `Documents/`, `vendor/` は除外）
- 大量のサブクラスがある場合は、Task ツール (Explore エージェント) を活用して並列に検索すること
