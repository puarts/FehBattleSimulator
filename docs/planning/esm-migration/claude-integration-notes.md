# 外部レビュー統合ノート

## レビュー元

- Gemini (gemini-3-pro-preview)
- OpenAI (gpt-5.4)

---

## 統合する指摘（重要度順）

### 1. フェーズ順序の再構成（両者共通・致命的）

**指摘**: ESM化（Phase 3）をVite/Vitest導入（Phase 4/5）より前に行うと、`export/import`を含むファイルがDeploy.batの単純結合やcreate_tests.shで壊れる。

**判断**: **統合する**。これは致命的な問題。フェーズ順序を以下に変更:
- Phase 3: Vite + Vitest の「器」を先に作る（まだグローバルスコープのまま）
- Phase 4: ESM化（Vite/Vitest環境の上で行う）
- Phase 5: クリーンアップ

### 2. Phase 2の分割（両者共通・重要）

**指摘**: 「ファイル移動とロジック変更は同時にやらない」という鉄則と、巨大ファイル分割をPhase 2に含めることが矛盾している。

**判断**: **統合する**。Phase 2を以下に分割:
- Phase 2a: 物理的なファイル移動のみ
- Phase 2b: 巨大ファイルの責務分割（BattleSimulatorBase等）

### 3. Strict Mode準拠化（Gemini）

**指摘**: ESM化するとStrict Modeが自動適用される。15万行のバニラJSに非Strict記述がある可能性。

**判断**: **統合する**。ESM化前に`"use strict"`を全ファイルに追加して問題を検出・修正するステップを追加。

### 4. g_appDataの明示的初期化（OpenAI）

**指摘**: トップレベル即時生成ではなく`init/get`パターンにすべき。

**判断**: **統合する**。ESM化時のg_appDataの扱いとして`initAppData()`/`getAppData()`パターンを採用方針に追加。

### 5. Deploy.bat互換の定義明確化（OpenAI・重要）

**指摘**: ESM化後のコードを単純結合してもSyntaxErrorになる。Deploy.batの互換を「操作手順互換」と「出力生成方法互換」のどちらにするか不明確。

**判断**: **統合する**。Deploy.batは最終的にVite buildのラッパーに置き換える方針を明記。移行中は旧方式を維持するが、ESM化完了後にVite buildに切替。

### 6. 依存分析の強化（OpenAI）

**指摘**: `madge`等はグローバルJSには使えない。静的解析+実行時トレースの二段構えが必要。

**判断**: **統合する**。カスタムAST解析スクリプト + ESLint `no-undef` + 実行時グローバル差分を組み合わせる方針に変更。

### 7. Jest/Vitest併存期間（OpenAI）

**指摘**: いきなりJestを削除せず、併存期間を設けるべき。

**判断**: **統合する**。Vitest追加 → 並行運用 → Jest削除の3ステップに変更。

### 8. 副作用の分類（OpenAI）

**指摘**: ファイルの副作用を分類（pure-definition / side-effectful / initialization-root等）し、ESM化順序に反映すべき。

**判断**: **統合する**。Phase 1の成果物に副作用分類を追加。

### 9. globalThis互換レイヤーのヘルパー統一（OpenAI）

**指摘**: `exposeLegacyGlobal()`のような統一ヘルパーで管理すべき。

**判断**: **統合する**。トレーサビリティとクリーンアップの容易さのため。

### 10. ブラウザスモークテスト（OpenAI）

**指摘**: jsdomだけでは不十分。8ページの起動確認を自動化すべき。

**判断**: **部分統合**。検証チェックリストに「各ページの起動確認」を追加。ただしPlaywright導入はスコープが大きいため、Phase 5完了後の改善項目とする。

## 統合しない指摘

### イベントバス禁止原則（OpenAI）

**理由**: 循環依存の対処としてイベントバスは元々検討していない。計画から言及を削除すれば十分。

### セキュリティ関連（CDN SRI、localStorage検証等）（OpenAI）

**理由**: 今回の移行スコープ外。別途セキュリティ改善として扱うべき。

### ADR（Architecture Decision Record）導入（OpenAI）

**理由**: 良い提案だが、deep-plan自体が意思決定の記録として機能している。追加のフォーマットは過剰。

### sourcemap方針の詳細化（OpenAI）

**理由**: Viteのデフォルト設定で十分。問題が発生した時点で対処。

### Viteバージョン固定（OpenAI）

**理由**: 実装時に最新安定版を採用すれば十分。計画段階で固定する必要なし。

### ESLint強化の詳細スケジュール（OpenAI）

**理由**: 各フェーズで必要に応じて設定を追加すれば十分。個別計画は不要。

### Vue統合レイヤー切り出しの後回し（OpenAI）

**理由**: 妥当な指摘。BattleSimulatorBase分割時にVue統合部分は最後に回す方針を追加。

### キャッシュバスティング設計（Gemini）

**理由**: Deploy.batがVite buildラッパーに置き換わる時点で対処。現時点では詳細設計不要。

### 開発時ファイルリクエスト過多（Gemini）

**理由**: Viteのデフォルト最適化で十分。問題が発生してから`optimizeDeps`で対処。
