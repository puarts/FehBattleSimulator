# FEH Battle Simulator — 大規模テスト計画 Spec

## 概要

FEH Battle Simulatorのテストカバレッジを大幅に拡充し、品質と信頼性を段階的に向上させる。
現在188テスト（6ファイル）から、スキル実装・戦闘ロジック・インフラの3軸で網羅的なテスト基盤を構築する。

## 背景・動機

- スキル実装が急速に増加中（SkillImpl202601.js等）だが、個別スキルの動作検証テストが不足
- 戦闘ロジック（追撃判定・奥義発動・戦闘順序）のエッジケーステストが限定的
- テストヘルパーが最小限で、新規テスト追加の敷居が高い
- カバレッジ測定やパフォーマンス回帰検知の仕組みがない

## 現状

- **テストファイル**: 6ファイル（DamageCalculator, SkillEffect, BeginningOfTurnSkillHandler, GetRequirements, UnitManager, SimpleUtility）
- **テスト数**: 188テスト、全パス
- **テスト基盤**: Jest + jsdom、create_tests.shで全ソースを結合してAll.test.jsとして実行
- **CI**: GitHub Actions（Jekyll build + Jest + ESLint）
- **カバレッジ**: 未測定

## 対象領域

### Phase 1: インフラ・品質改善（基盤整備）

テスト追加を効率化するための基盤を先に整備する。

- **テストヘルパー拡充**: ユニット生成・スキル装備・戦闘実行を簡潔に記述できるユーティリティ
  - ビルダーパターンでユニットを構築（武器・スキル・ステータス指定）
  - 戦闘シナリオを宣言的に記述・実行するヘルパー
  - スキル効果のアサーション用マッチャー
- **カバレッジ測定導入**: Jest coverage設定、CIでのカバレッジレポート出力
- **パフォーマンス回帰テスト**: 主要処理（1391ユニット戦闘等）の実行時間ベースライン設定と閾値チェック
- **テストカテゴリ整理**: ファイル分割方針の策定（ドメイン別、速度別）

### Phase 2: スキル実装テスト

個別スキルの効果が正しく発動するかの網羅的テスト。

- **DSLノード単体テスト**: 各ノードタイプ（GRANTS_BONUS, INFLICTS_PENALTY, DEALS_DAMAGE, REDUCES_DAMAGE等）の単体動作確認
- **スキルカテゴリ別テスト**:
  - 武器スキル（錬成含む）
  - 補助スキル（応援・移動補助・歌う踊る）
  - 奥義スキル（攻撃奥義・防御奥義・特殊奥義）
  - Aスキル・Bスキル・Cスキル・聖印
- **スキル相互作用テスト**:
  - 無効化 vs 無効化無効（見切り系）
  - スタック・上書きルール
  - 条件付きスキルの発動条件境界値
- **新規スキル追加時のテストテンプレート**: スキル実装と同時にテストを書くためのパターン確立

### Phase 3: 戦闘ロジックテスト

戦闘の各フェーズを網羅的にテスト。

- **ダメージ計算拡充**:
  - 属性相性（有利・不利・無効）
  - 特効（竜・騎馬・飛行・重装・獣等）
  - 守備/魔防の低い方参照
  - ダメージ軽減の累積・順序
- **追撃判定**:
  - 速さ基準追撃
  - 絶対追撃・追撃不可
  - 絶対追撃 vs 追撃不可の優先度
- **奥義関連**:
  - カウント加速・減速
  - 奥義発動タイミング（戦闘中・範囲・防御）
  - 奥義抑制スキルとの相互作用
- **戦闘フロー**:
  - 戦闘前スキル（先制奥義、ブレード系）
  - 戦闘中スキル適用順序
  - 戦闘後スキル（回復、デバフ付与、再移動）
  - 反撃不可・反撃可能の判定
- **ターン開始・終了処理**:
  - ターン開始時スキル（回復・ダメージ・バフ・デバフ）
  - パニック・キャンセル等のステータス効果処理

## 成功基準

- テスト数: 500+（現188から大幅増）
- 新規スキル実装時にテストテンプレートが使える状態
- CIでカバレッジレポートが確認可能
- パフォーマンス回帰を自動検知可能
- 主要な戦闘ロジックのエッジケースがカバーされている

## 制約・考慮事項

- テスト基盤はcreate_tests.shによる結合方式を維持（大規模リファクタリングは避ける）
- 新規ソースファイル追加時はcreate_tests.shのSOURCE_FILE_NAMESへの登録が必要
- jsdom環境での実行（ブラウザAPIの制約あり）
- テスト実行時間が過度に増加しないよう配慮（現在約6秒）
