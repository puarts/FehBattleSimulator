# 外部レビュー統合ノート

## Gemini Review (iteration-1-gemini.md) — 2026-03-19 再レビュー

### 統合する提案

#### 1. パフォーマンステストのウォームアップ実行 (Gemini 2.1)
- **提案**: JITコンパイルのオーバーヘッドを避けるため、計測前にウォームアップ実行を追加
- **理由**: V8のJIT特性上、初回実行は数十倍遅くなりうる。CI環境でのFlaky test回避に有効
- **統合方法**: セクション5.2のパフォーマンスベンチマーク実装にウォームアップループを追加

#### 2. TestDummyユニットの標準化 (Gemini 3.1)
- **提案**: スキルロジックテストには実在英雄ではなく固定ステータスのTestDummyを使用
- **理由**: 英雄のベースステータス変更（神竜の花上限解放等）でスキルロジックと無関係にテストが壊れるリスク
- **統合方法**: UnitBuilderに`createDummy()`メソッドを追加、スキルテストテンプレートでの標準使用を明記

#### 3. グローバル状態リセットの拡充 (Gemini 3.2)
- **提案**: `g_appData = null`だけでなく、奥義カウント・状態付与キャッシュ等もリセット
- **理由**: FEHシミュレータ固有の状態漏洩リスク
- **統合方法**: セクション3.3のresetGlobalTestState()に詳細リセット項目を追加

#### 4. FEH固有エッジケースの追加 (Gemini 3.3)
- **提案**: HP条件評価タイミング、虚勢の適用範囲、相性激化/相殺のテスト
- **理由**: FEHで最もバグが起きやすい相互作用
- **統合方法**: セクション7に追加テスト項目として記載

#### 5. AIエージェント向けガイドライン (Gemini 4.2)
- **提案**: AIはrun_tests.sh経由でテスト実行し、結合ファイルを直接読まないこと
- **理由**: コンテキストウィンドウの効率的使用
- **統合方法**: セクション2にAIエージェント向けのガイドラインを追加

#### 6. カバレッジが結合方式で動作しない問題 (前回レビューから継続)
- **対応**: All.test.js単体ファイルの行カバレッジとして受け入れる方針に変更済み

#### 7. run_tests.sh連携 (前回レビューから継続)
- **対応**: run_tests.shのカテゴリ引数転送を計画に追加済み

#### 8. CI環境のパフォーマンス閾値 (前回レビューから継続)
- **対応**: 閾値を5x以上に設定する方針で対応済み

### 統合しない提案

#### 1. スナップショットのカスタムJSON保存 (Gemini 1.1)
- **理由**: 現在のプランではJestの`toMatchSnapshot`は使用しない。`RegressionTestHelper`はスナップショット値を抽出して`expect(値).toBe(期待値)`で比較する方式であり、`.snap`ファイルは生成されない。

#### 2. ソースマップ生成 (Gemini 1.2)
- **理由**: ソースマップ生成は`create_tests.sh`に大幅な複雑性を追加する。現時点ではAll.test.js全体のカバレッジ率で進捗を追跡する方針で十分。

#### 3. ディレクトリベースのテストファイル検索 (Gemini 1.3)
- **理由**: テストファイルのサブディレクトリ分割は既存のflat構造からの大きな変更。case文方式でも新規ファイル追加時のメンテナンスコストは許容範囲。CIで全カテゴリ実行を確認する注記を追加することで対応。

#### 4. 並行実行時のファイル競合対策 (Gemini 4.1)
- **理由**: 現在のCI/ローカル実行は逐次的であり、並行実行のユースケースは想定していない。

#### 5. パフォーマンステストのWarningアノテーション化 (Gemini 2.1代替案)
- **理由**: ウォームアップ+十分な閾値マージン（5倍）で安定性は確保できる。閾値超過はテスト失敗として検出する方が確実。
