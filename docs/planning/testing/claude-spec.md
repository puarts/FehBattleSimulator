# FEH Battle Simulator — 大規模テスト計画 統合仕様

## 概要

FEH Battle Simulatorのテストカバレッジを大幅に拡充し、品質と信頼性を段階的に向上させる。現在188テスト（6ファイル）から500+テストへ拡大し、スキル実装・戦闘ロジック・インフラの3軸で網羅的なテスト基盤を構築する。

## 現状

- **テストファイル**: 6ファイル（DamageCalculator, SkillEffect, BeginningOfTurnSkillHandler, GetRequirements, UnitManager, SimpleUtility）
- **テスト数**: 188テスト、全パス
- **テスト基盤**: Jest + jsdom、create_tests.shで44ソースファイルを結合してAll.test.jsとして実行
- **CI**: GitHub Actions（Jekyll build + Jest + ESLint）
- **カバレッジ**: 未測定（jest.config.jsにcoverageProvider: "v8"は設定済み）
- **既存ヘルパー**: test_HeroDatabase, test_DamageCalculator, test_BeginningOfTurnSkillHandler, test_createDefaultUnit
- **実行時間**: 約6秒

## 要件（インタビュー結果を反映）

### テストヘルパー・ビルダー

- 既存test_HeroDatabaseベースのヘルパーを拡張する形で新ビルダーパターンを導入
- 武器・スキル・ステータスを宣言的に指定できるフルーエントAPIの提供
- 戦闘シナリオを宣言的に記述・実行するヘルパー
- 既存テストは変更せず共存させる

### カバレッジ測定

- Jest coverage設定を有効化
- 初期閾値は低めから開始し、段階的に引き上げ
- CIでのカバレッジレポート出力（PRコメント）
- 閾値の扱い（ビルド失敗/警告）は段階的に判断

### パフォーマンス回帰テスト

- 主要ベンチマーク: 全英雄戦闘（追跡対象の計算: 238ms がベースライン）
- 追加ボトルネック候補はコードベース調査で特定
- 手動タイミング（既存test_executeTest/ScopedStopwatch活用）で開始

### テスト分割実行

- **重要要件**: AIエージェント（Claude Code等）がちょっとした修正後の確認で使えるよう、分割実行しやすい構造に
- create_tests.shの結合方式を維持しつつ、特定カテゴリのテストだけ実行可能にする
- 全テスト合計は30秒以内
- 個別スキル実装時は関連テストのみ実行可能に

### スキルテスト優先度

- **最新スキル優先**: SkillImpl202601.js の最新スキルほど重点的にテスト
- **古いスキル**: コードを見て必要がありそうであればピックアップ
- 新規スキル追加時のテストテンプレート確立

### 戦闘ロジックテスト — 重点エリア

ユーザーが特定した問題が発生しやすいエリア:
1. **奥義カウント変動**: 戦闘中の各種カウント加速・減速・リセット
2. **再行動 (Grant another action)**: Canto、再移動系スキル
3. **祈り (Miracle系)**: HP1で耐える効果
4. **回復不可**: 回復を無効化するスキル
5. **暗闘 (Feud)**: 特定条件でのバフ無効化
6. **スタイル**: スタイル効果の適用

### テスト検証方法

- **リグレッションテスト方式**: 現在の動作を「正」として固定し、変更時の回帰を検出
- 手動計算値による検証は重要な新規テストに限定

## 技術的制約

- テスト基盤はcreate_tests.shによる結合方式を維持
- 新規ソースファイル追加時はcreate_tests.shのSOURCE_FILE_NAMESへの登録が必要
- jsdom環境での実行（ブラウザAPIの制約あり）
- テスト合計実行時間30秒以内

## 成功基準

- テスト数: 500+（現188から大幅増）
- 新規スキル実装時にテストテンプレートが使える状態
- CIでカバレッジレポートが確認可能
- パフォーマンス回帰を自動検知可能
- 主要な戦闘ロジックのエッジケースがカバーされている
- AIエージェントが特定テストのみ実行可能な分割構造
