## 1. 潜在的な落とし穴とエッジケース (Footguns & Edge Cases)

### A. `let` / `const` と HTML `loadScripts` のスコープの差異 (重要)
*関連セクション: 2. 技術的制約, 4.3 Step B-2*

本番（`Deploy.bat`）やテスト（`create_tests.sh`）は単純なファイル結合（Concatenation）であるため、トップレベルで宣言された `let` や `const` は結合後のファイル内で共有されます。
しかし、HTMLの `loadScripts` が `<script>` タグを動的にDOMに追加する方式の場合、**各ファイルは別々のスクリプトスコープ**となります。
`var` や `function` で宣言されたものはグローバル（`window`）にアタッチされるため別ファイルから参照可能ですが、`let` や `const` で宣言された定数（例: `CALC_HEAL_AMOUNT_HOOKS` や `IS_DEBUFFER_TIER_1_HOOKS` など）は **グローバルオブジェクトにアタッチされず、別ファイルから参照すると `ReferenceError` になります。**

* **アクション**: 抽出するクラスやユーティリティ関数、およびそれらが依存するフック変数が `let` / `const` ではなく `var` で宣言されているか、あるいは `window.CALC_HEAL_AMOUNT_HOOKS` のように明示的にグローバルにエクスポートされているかを確認・修正してください。

### B. `instanceof` と Temporal Dead Zone (TDZ)
*関連セクション: 4.2 Step B-1*

`UnitContext.js` は `Unit.js` の**直前**にロードされます。
もし `UnitContext.js` 内のクラス（例: `AttackEvaluationContext` 等）のメソッド外（クラスの静的プロパティの初期化時など）で `Unit` クラスを参照していたり、`instanceof Unit` を評価しようとしたりすると、`Unit` がまだ定義されていないためエラー（またはTDZによる例外）が発生します。

* **アクション**: 抽出対象の4クラスが、**「パース/ロード時」に `Unit` シンボルを評価していないこと**を確実にしてださい。（メソッドの中でのみ `Unit` を参照しているなら、実行時解決されるため問題ありません）。

### C. ESLint の `no-undef` エラー
*関連セクション: 2. テスト方式*

コードを別ファイルに切り出すと、今まで同一ファイル内にあったためESLintを通過していたシンボル参照が、未定義（`no-undef`）としてESLintに怒られる可能性が高いです。

* **アクション**: 新規作成するファイルの先頭に `/* global Unit, CombatResultType, Support, StatusEffectType, ... */` のようなグローバル宣言コメントを追加するか、プロジェクトの `.eslintrc` の `globals` セクションにこれらのシンボルを追加するタスクを計画に明記してください。
