# 外部レビューフィードバック統合ノート

## レビュー元: Gemini (gemini-3-pro-preview)

---

## 統合する指摘

### 1. Vue 3 のランタイムコンパイラ設定 (esm-bundler) — **統合する**

**指摘**: HTML内のVueテンプレート（`{{ }}`、`v-if` 等）をVue 3で使うには、デフォルトのランタイム専用ビルドではなく、コンパイラ込みのビルド（`vue/dist/vue.esm-bundler.js`）をエイリアスで指定する必要がある。

**統合理由**: 本プロジェクトはSFCを使っておらず、HTML内にVueテンプレートを直接記述している。これはVue 3移行における致命的な要件であり、見落とすと画面が真っ白になる。

**対応**: Step D の vite.config.js に `resolve.alias` を追加。

### 2. グローバル変数のVue 3テンプレート参照制限 — **統合する**

**指摘**: Vue 3ではコンポーネントの`data`/`setup`/`methods`で明示的に定義されていないグローバル変数をテンプレートから直接参照できなくなった。

**統合理由**: 現在のコードは `g_appData` 等のグローバル変数をテンプレートで使用している可能性がある。`app.config.globalProperties` への登録や、`data`/`computed` での明示的な定義が必要。

**対応**: Step D に明示的なグローバル変数対応タスクを追加。

### 3. Vitest の並列実行によるグローバル状態汚染 — **統合する**

**指摘**: Vitestはデフォルトでテストファイルを並列実行するが、元々単一結合スクリプトで動いていたテストはグローバル状態を共有している可能性がある。

**統合理由**: テスト安定性に直結する重要な指摘。段階的移行の初期段階でflakyテストに悩まされるのを避けるべき。

**対応**: Step B に `singleThread: true` の設定を追加。全テスト移行完了後に並列化を検討。

### 4. Vue.set / $set の廃止対応 — **統合する**

**指摘**: Vue 3はProxyベースになったため、`Vue.set()` / `this.$set()` / `this.$delete()` が廃止された。レガシーコードに残っている可能性がある。

**統合理由**: これを見落とすとランタイムエラーになる。Step D の初期段階でgrepして置換するタスクとして追加。

**対応**: Step D.6 に `$set`, `$delete`, `Vue.set` のgrep/置換タスクを追加。

### 5. Vite の root 設定とアセット解決 — **統合する**

**指摘**: HTMLファイルが `Sources/` 配下にあるため、`root: 'Sources'` と `build.outDir: '../dist'` を設定しないと、dev serverのURL構造や相対パスの解決が壊れる可能性がある。

**統合理由**: プロジェクト構造に起因する具体的な設定要件。dev server の使い勝手に直結する。

**対応**: Step A.2 に root 設定の詳細を追加。

## 統合しない指摘

### 1. 1ファイル出力の代わりに8回ループビルド — **統合しない**

**指摘**: Viteのマルチページモードではなく、8回個別ビルドを実行するスクリプトの方が確実。

**不統合理由**: Rollup の設定（`manualChunks` や `output.inlineDynamicImports`）でマルチページモードのまま1ファイル出力は実現可能。8回ビルドはビルド時間が大幅に増加するため、まずはマルチページモードでの実現を試み、困難な場合のフォールバックとして記載する。

### 2. Step DとEの順序入れ替え（Select2をVue 3前に置換）— **統合しない**

**指摘**: jQuery/Select2をVue 2環境で先に置換してからVue 3に移行した方が問題の切り分けが容易。

**不統合理由**: ユーザーが「段階的に移行」と回答しており、Vue 3移行を先に行う方が全体のスコープが明確。Select2のVueラッパーコンポーネントは比較的独立しており、Vue 3環境でも動作確認しやすい。ただし、Step Dの注意事項としてSelect2との互換性問題の可能性を明記する。

### 3. npm audit / Dependabot の導入 — **統合しない**

**指摘**: CDNからnpmへの移行で依存ツリーが深くなるため、依存関係自動更新ツールの導入を検討。

**不統合理由**: Phase 3のスコープ外。セキュリティプラクティスとしては有効だが、本計画の目的（ビルドツール移行）とは直接関係しない。将来のタスクとして検討可能。

### 4. プロトタイプ作成の推奨 — **統合しない**

**指摘**: Step A〜Dのミニマム検証をプロトタイプとして先に行うべき。

**不統合理由**: 段階的移行の各ステップ自体が実質的にプロトタイプ→検証→本実装のサイクルになっている。別途プロトタイプを作成する必要はない。
