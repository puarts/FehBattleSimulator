# Phase 3 インタビュー記録

## Q1. 移行の優先順位と段階分け

**質問**: 5つの目標（Vite ビルド、Vitest、Vite dev server、Vue 3 + Pinia、jQuery 除去）をどの順序で進めたいですか？

**回答**: **段階的に移行**。各ステップで動作確認しながら進める。例: Vite ビルド → Vitest → Vue 3 → jQuery 除去。

## Q2. UI 部品（Vue.Draggable / Select2）の代替

**質問**: Vue.Draggable と Select2 について、Vue 3 互換の代替ライブラリを使うか、独自実装するか？

**回答**: **お任せ**。調査結果に基づいて最適な選択肢を提案してほしい。

## Q3. 本番デプロイフロー

**質問**: Vite 移行後も `dist/` に結合 JS を出力する現行フローを維持する必要があるか？

**回答**: **現状維持**。担当者が別なのでまずは現行フローを維持。その後対応してもらう予定。

## Q4. Vite ビルドの出力形式

**質問**: Vite 移行後も「HTML ごとに1つの結合 JS」形式を維持するか、コード分割を利用するか？

**回答**: **1ファイル維持**。デプロイ担当者への影響を最小化するため。

## Q5. SkillImpl ファイルのコンフリクト対策

**質問**: Phase 3 で SkillImpl ファイルの import/export 文やモジュール構造を変更する必要があるか？

**回答**: **Phase 2 のまま使う**。既存の import/export 文をそのまま活用し、コンフリクトリスクを最小化。

## Q6. ローカル/本番のデータ読み込み

**質問**: Vite dev server 移行後もローカル/本番のデータ読み込み分岐パターンを維持するか？

**回答**: **統一したい**。環境変数や Vite の設定で切り替える方式に変更したい。

## Q7. テストの対象範囲

**質問**: Vitest 移行時に「全テストがパスすること」を必須条件とするか？Jest 環境も並行して維持するか？

**回答**: **段階的に移行**。まず主要テストを Vitest に移行し、全完了後に Jest を削除。

## Q8. ブラウザサポート

**質問**: Vite の出力でサポートすべきブラウザの要件は？

**回答**: **ES2015 以上**。Vite のデフォルトターゲットに合わせる。

## Q9. CI/CD 更新

**質問**: Phase 3 で CI パイプラインも更新するか？

**回答**: **はい、CI も更新**。Jest → Vitest、build.mjs → vite build に CI を更新する。

## Q10. Phase 3 の完了条件

**質問**: 動作確認の基準は？

**回答**: **テスト全パス + 手動確認**。Vitest で全テストがパスし、かつブラウザで手動動作確認。
